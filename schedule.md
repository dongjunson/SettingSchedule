# PMS Supabase & TanStack Query Integration Plan

This document outlines the plan to integrate Supabase as the backend and TanStack Query for data fetching, replacing the current mock implementation.

## 1. Supabase Schema Design

We need three tables to normalize the current JSON structure.

### Tables

#### `sites`
Stores the project sites.
- `id`: `text` (Primary Key) - e.g., 'anyang-bakdal'
- `name`: `text` - e.g., '안양 박달 사업소'
- `created_at`: `timestamptz` (Default: now())

#### `timeline_items`
Stores the timeline tasks for each site.
- `id`: `bigint` (Primary Key, Identity)
- `site_id`: `text` (Foreign Key -> sites.id)
- `step`: `text` - e.g., '1-01'
- `task`: `text` - e.g., 'Kick-Off'
- `section`: `text` - e.g., '구축 및 설치'
- `subsection`: `text` (Nullable) - e.g., '사전 준비'
- `status`: `text` - 'pending' | 'working' | 'completed' (Default: 'pending')
- `role`: `text` - 'field' | 'rnd' | 'both'
- `start_date`: `date` (Nullable)
- `completion_date`: `date` (Nullable)
- `created_at`: `timestamptz` (Default: now())

#### `checklist_items`
Stores the checklist items for each site.
- `id`: `bigint` (Primary Key, Identity)
- `site_id`: `text` (Foreign Key -> sites.id)
- `text`: `text` - Description of the checklist item
- `checked`: `boolean` (Default: false)
- `created_at`: `timestamptz` (Default: now())

### SQL Initialization Script

```sql
-- Create sites table
CREATE TABLE sites (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Create timeline_items table
CREATE TABLE timeline_items (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  site_id TEXT REFERENCES sites(id) ON DELETE CASCADE,
  step TEXT NOT NULL,
  task TEXT NOT NULL,
  section TEXT NOT NULL,
  subsection TEXT,
  status TEXT DEFAULT 'pending' CHECK (status IN ('pending', 'working', 'completed')),
  role TEXT DEFAULT 'field' CHECK (role IN ('field', 'rnd', 'both')),
  start_date DATE,
  completion_date DATE,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Create checklist_items table
CREATE TABLE checklist_items (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  site_id TEXT REFERENCES sites(id) ON DELETE CASCADE,
  text TEXT NOT NULL,
  checked BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Enable RLS (Row Level Security) - Optional but recommended
ALTER TABLE sites ENABLE ROW LEVEL SECURITY;
ALTER TABLE timeline_items ENABLE ROW LEVEL SECURITY;
ALTER TABLE checklist_items ENABLE ROW LEVEL SECURITY;

-- Create policies (Allow public read/write for now for simplicity, refine later)
CREATE POLICY "Public read sites" ON sites FOR SELECT USING (true);
CREATE POLICY "Public update sites" ON sites FOR UPDATE USING (true);
CREATE POLICY "Public read timeline" ON timeline_items FOR SELECT USING (true);
CREATE POLICY "Public update timeline" ON timeline_items FOR UPDATE USING (true);
CREATE POLICY "Public read checklist" ON checklist_items FOR SELECT USING (true);
CREATE POLICY "Public update checklist" ON checklist_items FOR UPDATE USING (true);
```

## 2. API Specification (Supabase Client)

We will use the Supabase JavaScript Client directly.

### 2.1 Get All Sites with Progress
Since we need to calculate progress, we fetch sites and their related items.

- **Query**:
  ```typescript
  supabase
    .from('sites')
    .select(`
      *,
      timeline_items (*),
      checklist_items (*)
    `)
  ```

### 2.2 Get Single Site Detail
- **Query**:
  ```typescript
  supabase
    .from('sites')
    .select(`
      *,
      timeline_items (*),
      checklist_items (*)
    `)
    .eq('id', siteId)
    .single()
  ```

### 2.3 Update Timeline Item Status
- **Operation**: PATCH
- **Target**: `timeline_items` table
- **Params**: `id` (item ID), `status` (new status)
- **Code**:
  ```typescript
  supabase
    .from('timeline_items')
    .update({ status: newStatus })
    .eq('id', itemId)
  ```

### 2.4 Update Checklist Item
- **Operation**: PATCH
- **Target**: `checklist_items` table
- **Params**: `id` (item ID), `checked` (boolean)
- **Code**:
  ```typescript
  supabase
    .from('checklist_items')
    .update({ checked: isChecked })
    .eq('id', itemId)
  ```

## 3. Implementation Plan with TanStack Query

### Step 1: Install Dependencies
```bash
npm install @supabase/supabase-js @tanstack/react-query
```

### Step 2: Setup Supabase Client
Create `src/lib/supabase.js` to initialize the client with environment variables (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`).

### Step 3: Setup Query Client
Wrap the app in `QueryClientProvider` in `src/main.jsx`.

### Step 4: Create Custom Hooks
Create `src/hooks/useSites.js`:

1.  **`useSites`**: Fetches all sites.
    -   Key: `['sites']`
    -   Use `select` option to calculate progress metrics (timeline %, checklist %, etc.) derived from the raw data.

2.  **`useSite(siteId)`**: Fetches a specific site.
    -   Key: `['site', siteId]`
    -   Enabled only when `siteId` is present.

3.  **`useUpdateTimelineItem`**: Mutation.
    -   Mutation Function: Calls Supabase update.
    -   `onMutate`: Optimistic update (update cache immediately).
    -   `onError`: Rollback.
    -   `onSettled`: Invalidate `['site', siteId]`.

4.  **`useUpdateChecklistItem`**: Mutation.
    -   Similar structure to timeline update.

### Step 5: Migration (Replace Store)
Gradually replace usages of `useStore` with these hooks in:
-   `SiteSelection.jsx` (Use `useSites`)
-   `TimelinePage.jsx` (Use `useSite`, `useUpdateTimelineItem`)
-   `ChecklistPage.jsx` (Use `useSite`, `useUpdateChecklistItem`)

### Step 6: Data Seeding (One-time)
Create a script or utility to upload the hardcoded data from `src/lib/store.js` into Supabase to populate the initial database.
